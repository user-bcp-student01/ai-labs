# Hallazgos

## Componente auth — Discovery

`docs/ENDPOINTS.md` no existe; el contrato de `POST /auth/login` sigue siendo el observado en código, no uno acordado en documentación: ruta en `auth/src/main/java/com/bcp/workshop/auth/AuthResource.java:16,28-30`, validaciones `400` (`AuthResource.java:54-69`), credenciales inválidas `401` y respuesta válida `200` con `token`, `expiresIn`, `user` y `debug` (`AuthResource.java:37-45,73-84`). Los errores internos conservan `500` y las claves `message` y `exception`, ahora con valores genéricos (`AuthResource.java:46-51`). El flujo actual es Resource → `AuthService.authenticate` (`AuthService.java:11-12`) → `UserRepository.findByCredentials` (`UserRepository.java:58-73`), con SQLite configurable mediante `AUTH_DB_URL` o `jdbc:sqlite:./data/workshop.db` (`UserRepository.java:21`). El token firmado se genera mediante `AuthTokenService.create` (`AuthResource.java:83-84`).

La descripción inicial del flujo y las filas pendientes conservan el resultado histórico de Discovery. Las filas resueltas se actualizaron con evidencia del código posterior a los cambios. Para validar se usó una base SQLite ficticia local; CodeQL, Dependency Review y advisories externos no se ejecutaron.
